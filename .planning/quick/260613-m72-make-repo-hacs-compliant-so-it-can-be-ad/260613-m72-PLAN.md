    Steps:
    1. Create tag v3.1.1 pointing to the same commit as v3.1.1-rc.1:
       `git tag v3.1.1 v3.1.1-rc.1^{}` (dereference to commit, not tag)

    3. Create a stable GitHub release from that tag, uploading the dist/calendar-card-pro.js asset:
       `gh release create v3.1.1 dist/calendar-card-pro.js --title "v3.1.1 — iOS 12.5.8 Edition" --notes "Stable release of the iOS 12.5.8-compatible Calendar Card Pro fork. Identical to v3.1.1-rc.1." --latest`

    Do NOT delete the existing pre-release; just add the stable release alongside it.
    The release asset filename must remain exactly `calendar-card-pro.js` to match the hacs.json `filename` field.
  </action>
  <verify>
    <automated>gh release view v3.1.1 --json prerelease,assets --jq '{prerelease: .prerelease, assets: [.assets[].name]}'</automated>
  </verify>
  <done>gh release view v3.1.1 shows prerelease: false and assets includes calendar-card-pro.js</done>
</task>
