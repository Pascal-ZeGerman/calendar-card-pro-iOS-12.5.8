**Step 1: Install dependencies with the new Lit overrides**
```bash

```
This regenerates package-lock.json with the pinned Lit versions.

**Step 2: Verify Lit resolution**
```bash
npm ls lit
```
Expected output: a single `lit@2.8.0` (no lit@3.x anywhere in the tree). If you see lit@3.x, STOP — do not proceed. Check that package.json has both `"lit": "2.8.0"` in dependencies AND the overrides block. Re-run npm install and check again.

**Step 3: Also verify sub-packages**
```bash
npm ls lit-element lit-html @lit/reactive-element
```
Expected: lit-element@3.3.3, lit-html@2.8.0, @lit/reactive-element@1.6.3. If wrong versions appear, STOP and report.

**Step 4: Run the production build**
```bash
npm run build
```
This runs: `cross-env NODE_ENV=prod rollup -c && bash scripts/verify-bundle.sh`

The build must exit 0. If rollup fails, report the full error output. If verify-bundle.sh fails with a FAIL message, report which pattern failed and stop.

**Step 5: Calibrate the size ceiling in verify-bundle.sh**
After a successful build, get the actual bundle size:
```bash
du -k dist/calendar-card-pro.js
```
Take the reported size in KB, add 20% headroom (multiply by 1.2, round up to nearest integer), and update MAX_SIZE_KB in scripts/verify-bundle.sh to that value.

Example: If du reports 420KB, ceiling = ceil(420 * 1.2) = 504. Set MAX_SIZE_KB=504.

Then run `npm run build` again to confirm the calibrated size ceiling also passes (it should, since the bundle hasn't changed).

**Step 6: Manual bundle inspection — grep for forbidden patterns**
Run these directly to confirm the verify script result:
```bash
grep -cP '\?\.' dist/calendar-card-pro.js || true
grep -cP '[^?]\?\?[^?=]' dist/calendar-card-pro.js || true
grep -cP '(?<!["\x27`])#[a-zA-Z_$]' dist/calendar-card-pro.js || true
grep -cF '\p{' dist/calendar-card-pro.js || true
```
All four should return 0. Report the actual counts in the summary.

**Step 7: Also grep for Object.fromEntries and Array.flatMap (Phase 2 advance warning)**
```bash
grep -c "\.fromEntries(" dist/calendar-card-pro.js || true
grep -c "\.flatMap(" dist/calendar-card-pro.js || true
```
These are not Safari 12.0 compatible (added in 12.1). Do NOT fix them in this phase — just note the counts in the summary for Phase 2 planning.

**Step 8: Commit the build output**
```bash
git add dist/calendar-card-pro.js package-lock.json scripts/verify-bundle.sh
git commit -m "build(01-build-pipeline): produce Safari 12-compatible bundle

- esbuild target: safari12

- SYNTAX-01: replaced \\p{Emoji} regex with isEmoji() call
- BUILD-01/02/03: all config changes in place
- All four syntax checks pass
"
```
